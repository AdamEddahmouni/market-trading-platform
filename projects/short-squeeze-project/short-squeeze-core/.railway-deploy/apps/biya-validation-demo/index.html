What this conclusion is, and is not

This judges the recorded methodology — whether the original selection can be reproduced from evidence that existed when it was made. It is not a rating of the stock, a prediction, or a recommendation. A conclusion of insufficient evidence does not mean the original platform was wrong; it means the surviving record cannot show whether it was right.

Two different systems

The original platform

The screener as it ran in July 2026. It is treated here as a frozen historical baseline: this study describes what it did and never edits, re-runs, or corrects it.

The rebuilt research engine

A deterministic, offline reconstruction with strict point-in-time evidence handling. It is used to replay what could have been known at the moment of detection — and nothing that came later.

Detection timeline

    Why a window, not a timestamp

    No surviving artifact records a platform event time. The bounds come from when the screener run started and when its log was last written — filesystem facts, which bound an event but cannot pinpoint one. Claiming an exact time here would be a fabrication that made the replay look more precise than the evidence supports.

    The two findings that matter most

    The label promised a mechanism the formula never checked

    The “Prime / Subprime” classification awarded one point each for a price band, a percentage change, a relative-volume threshold, and a short-float floor. None of those four is a squeeze mechanic. Borrow fee, days to cover, and the volatility-compression signal were all computed and displayed — and never scored.

    So a stock could be labelled a squeeze setup on momentum alone. That is a usable discovery filter; it is not squeeze confirmation.

    A column was renamed to something it was not

    Roughly two hours before the review, the “Short Float %” column was relabelled “Short Interest %”. The arithmetic underneath was correct, but it is a percentage of float — while “short interest” conventionally means an absolute share count.

    The fix is to show both quantities under unambiguous labels. The formula itself needs no change.

    Evidence used

    Only non-sensitive artifacts are listed. Private correspondence, personal names, credentials, and local file paths are excluded from this page by the export process itself, not removed by hand.

      What the record does not contain

      No saved candidate row, screenshot, database record, or cached provider response for this ticker survives. The only direct platform record is an application log that contains no field values and no timestamps — every reference to the ticker in it is a data-fetch failure. Every original displayed value is therefore unknown, and unknown values are left unknown rather than reconstructed from later data.

      Point-in-time replay

      Because detection is bounded rather than exact, the replay is run at both edges of the window. Running one and choosing the better-looking result is exactly the error this design prevents.

        Both replays return no eligible evidence, because no observation of any kind exists for this ticker in the archive. That empty result is the finding, not a gap in the method.

        Retrospective evidence amendment

        One detection window. Two boundary checks.

        The same versioned reference-price rule is applied at both edges of the bounded detection window. No favorable edge is selected after the fact.

        The methodology boundary

        Later price movement can confirm the outcome but cannot reconstruct or validate missing original platform inputs. This amendment changes the outcome finding, not the forensic finding about the original methodology.

        Limitations

          On generalising from one case

          One case cannot validate or invalidate a methodology. This study reconstructs a single identification in depth and builds a repeatable format for doing the same with others; it does not establish a hit rate, an expected return, or a claim about the approach as a whole.
