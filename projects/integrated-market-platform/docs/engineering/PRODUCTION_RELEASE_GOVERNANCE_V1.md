# Production Release Governance & Full-System Operational Acceptance (BUILD 35)

> **A release is accepted only when one exact artifact, configuration/policy envelope, and evidence bundle satisfy a pre-declared release-governance policy. Acceptance permits only the supervised operating scope explicitly granted; it does not authorize individual live sessions or orders.**

## Core Principle

BUILD 35 governs **which exact release is allowed to become the accepted supervised operational release**:

```text
BUILD 34 = deployment mechanics (package, deploy, rollback)
BUILD 35 = release governance + full-system acceptance
```

Release governance is separate from model governance (BUILD 20), runtime activation (BUILD 23), and deployment (BUILD 34):

```text
Release approval        ≠  Model promotion
Release approval        ≠  Runtime activation
Release approval        ≠  Live session authorization
Release approval        ≠  Order confirmation
```

## Release Lifecycle

```text
source
→ release artifact (BUILD 34)
→ release evidence bundle
→ production release candidate
→ eligibility assessment
→ release approval (human-governed)
→ environment promotion
→ deployment
→ operation
→ supersession / revocation
```

## Evidence Requirements

Every accepted release decision references exact immutable evidence IDs. The evidence bundle must prove lineage compatibility — evidence from incompatible release versions cannot be combined.

Evidence may carry forward only when proven safe (unchanged scientific implementation, docs-only delta, deployment-only metadata).

## Environment Promotion

Promotion obeys BUILD 34 same-artifact rule. Mandatory stages cannot be skipped:

```text
TEST → QUALIFICATION → SUPERVISED_PILOT → SUPERVISED_LIVE
```

`SUPERVISED_PILOT → SUPERVISED_LIVE` requires BUILD33 pilot evidence, BUILD34 deployment evidence, and BUILD35 release approval.

## Change Windows

A valid deployment window permits governed software change. It does **not** authorize trading.

Default for non-emergency deployment with active ambiguous orders: **BLOCK**.

Prerequisites: reconciled account, backup verified, live submissions blocked.

## Revocation

Release approval is revocable for critical safety defects, artifact integrity violations, security vulnerabilities, invalidated qualification evidence, and deployment drift.

Revocation blocks new deployment/promotion and preserves historical evidence (no history rewrite).

## Full-System Acceptance

29 domains evaluated across BUILD 01–34 architecture. One blocking domain failure defeats global acceptance regardless of aggregate test count.

Final dispositions:

- `FULL_SYSTEM_ACCEPTED_FOR_SUPERVISED_OPERATION`
- `FULL_SYSTEM_ACCEPTED_WITH_LIMITATIONS`
- `REQUIRES_REQUALIFICATION`
- `NOT_OPERATIONALLY_ACCEPTABLE`
- `INVALID_EVIDENCE`

Never: `AUTONOMOUS_TRADING_APPROVED`
